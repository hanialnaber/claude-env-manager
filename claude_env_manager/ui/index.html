03Cloud sessions

Keys for Claude in the cloud.

Cloud sessions run on Anthropic's machines, so they never read the settings on this computer. Their variables live on the cloud environment, and you add them there once.

Set it up

  1. Open Claude Code on the web and go to the settings of the environment your sessions use.
  2. Find Environment variables. They take .env format, one KEY=value per line.
  3. Paste the lines you copy below and save.
  4. Start a new session. Running sessions keep their old values until their machine is rebuilt.
  5. Check it arrived with the one-liner below. It prints the length, never the value.
Good to know. Anyone who can use that environment can read its variables, and any command Claude runs can see them. For an API key that only needs to reach one service, the docs suggest a network secret on the environment instead, which can't be read inside the session. A repo's shared .claude/settings.json is read in cloud sessions only for a single repo outside a Claude project, so don't rely on it, and never commit keys there.

04How it works

          
Where Claude finds your keys.

          
Claude Code reads environment variables from a few places, in a fixed order, and cloud sessions read from a different place entirely. Most "Claude can't see my key" problems come down to one of the cases below.

        


        
Two kinds of Claude

        

          

            
On this computer

            
Claude Code in your terminal, editor or desktop app

            
Reads the settings files on this computer, plus the shell it was started from. This app manages exactly these files.

            
          

          

            
In the cloud

            
Claude Code on the web and cloud sessions

            
Runs on Anthropic's machines and never sees this computer's files. Its keys go in the cloud environment's Environment variables setting.

            
          

        


        
The order Claude on this computer reads them

        

          
When the same name is set in more than one place, the highest one wins.

          
    
            
  1. 01
    ManagedSet by an administrator. Can't be overridden.managed-settings.json
    2. 
            
  2. 02
    Project localThis project, just you. The best home for a project's keys. Keep it out of git.<repo>/.claude/settings.local.json
    3. 
            
  3. 03
    Project sharedCommitted to the repo and shared with everyone. Never put secrets here.<repo>/.claude/settings.json
    4. 
            
  4. 04
    UserEvery project on this computer.~/.claude/settings.json
    5. 
            
  5. 05
    Your shellOnly when Claude is started from a terminal that has the variable. Any settings file wins over it.export FAL_KEY=…

Claude can't see my key

        

          
    
            
  1. Is it a cloud session? Cloud sessions ignore every file on this computer. Add the key to the cloud environment, then start a new session. 
    2. 
            
  2. Is it set at all? Type the name into the check on the Monitor page. 
    3. 
            
  3. Is another value winning? If the same name is set higher up, that value is the one Claude gets. Monitor shows where it comes from and what it overrides.
    4. 
            
  4. Is it only in your shell? Claude started from the Dock, Start menu or an editor won't have it. Put it in User or Project local instead.
    5. 
            
  5. Is it a name Claude ignores in project files? A few, like OTEL_* and CLAUDE_CONFIG_DIR, only count from User settings or your shell. The app flags these.
    6. 
            
  6. Did you just remove it? New and changed values apply on save. A removed variable only disappears when Claude is relaunched.
    7. 
            
  7. Does the value use ~ or $HOME? Values are used exactly as written. Write the full path.
    8. 
          

        


        
Keeping keys safe

        

          
Out of git
Project shared settings are committed. Keep keys in Project local or User, and make sure settings.local.json is ignored. The app warns you when it isn't.

          
Readable by your tools
Any command Claude runs can read the variables it was given, on this computer and in the cloud. Only give Claude the keys a task needs.

          
Shared in the cloud
Everyone who uses a cloud environment can read its variables. For a key that only calls one service, a network secret is safer.

        


        
What this app does

        

          
    
            
  • Runs only on your computer. It listens on 127.0.0.1, with a new random token each run, and makes no outside network calls.
    • 
            
  • Shows values only when you ask. The page gets names, a mask and the length. A value is sent only when you press Reveal or copy .env lines.
    • 
            
  • Edits safely. It keeps every other setting in the file, writes atomically, and creates new files readable only by you. A file with broken JSON is left alone.
